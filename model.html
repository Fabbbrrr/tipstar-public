Scoring: conditional logit (softmax over runners)

For each race, every runner gets a linear score u_i = coef . features_i. Win probabilities are the softmax of those scores across the runners in that race: p_model_i = exp(u_i) / sum(exp(u_j)). This is a standard discrete-choice / conditional-logit setup - it guarantees the modelled probabilities sum to 1 within a race, unlike scoring each runner in isolation.

edge_i = p_model_i / p_mkt_i, where p_mkt_i is the field's overround-normalised implied probability from fixed_win prices (1/price, renormalised to sum to 1 across the race). An edge of 1.30 means the model thinks a runner is 30% more likely to win than the market's own probabilities imply.

Fitting coefficients: tipstar.model.train()

Plain-Python gradient ascent on the conditional-logit log-likelihood - no numpy, no external deps. Feed it (feats, winner_index) pairs built from your own settled historical races (features.build_race on a RaceCard with results populated tells you which runner won). Comes with light L2 shrinkage (l2=1.0 by default) since some features (barrier dummies especially) are sparse.

model.EXAMPLE_COEF is not a fitted model - see GAPS.md. It sets every weight to 0 except lp_mkt=1.0, which makes p_model reproduce p_mkt exactly (softmax of log(p_mkt), renormalised, is just p_mkt again), so edge is always exactly 1.0. It exists purely so --mock --dry runs without crashing.

Selection (tipstar/selection.py)

  1. qualify: keep only each race's single top-rated runner

(rank == 1), only if edge &gt;= edge_min and the price falls in [price_min, price_max]. Defaults: edge_min=1.30, price_min=3.00, price_max=12.00 - narrow favourites and long-shots are excluded on purpose, since both are where a model built on ~20 hand-picked features is least trustworthy.

  1. diversify: caps how many selections can share a trainer/kennel

or a track (max_per_trainer=2, max_per_track=2 by default), so one noisy signal can't dominate the whole list.

  1. cap: at most max_tips (default 6) selections total.

Audit (tipstar/audit.py)

Re-derives what the pipeline would have tipped on a past date, using a trainer-form table built only from data before that date (refresh_trainer_strike_rates over [date - form_days - 7, date - 1]) and race odds rewound to lead_seconds before the advertised jump (features.snapshot_odds), then settles those picks against the real results. This is a standard walk-forward check: reusing today's trainer table to audit last week would leak information the live run could never have had, and would flatter the record.

What this is / isn't

Everything above produces a relative-value estimate versus the market, conditioned on whatever coefficients you trained. It is not a prediction that a given runner will win, it has not been validated against real outcomes by this repo, and 32%+ book overround (typical for fixed-odds racing markets) means flat-staking any price band is a losing game before you even get to whether the model is any good. See GAPS.md.

Model outputs are relative-value estimates from an unvalidated model — not outcome predictions and not financial or betting advice.
